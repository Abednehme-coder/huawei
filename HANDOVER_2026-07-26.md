# Statistically-validated ground truth for the SYN-flood packet-image model

## Context

This repo trains a ResNeXt-50 (MindSpore/mindcv) classifier that turns raw
CICDDoS2019 PCAP traffic into 224x224 grayscale images and detects
`ddos` vs `normal`. It's being written up for an IEEE-style conference paper
due **2026-08-05**. The team wants the paper to survive review on scientific
merit, not just be "ResNet swapped for ResNeXt, ported to MindSpore."

Investigation this session found the current primary model (0.3s time-window,
`per_second_0p3_focal_v2`) is **methodologically better than the paper's own
text describes** — images are built from all packets for both classes (no
class-conditional leak), and labels come from CIC's own officially-published
SYN attack-execution schedule (verified against CIC's public page: 11:28-17:35
day 1, 13:29-13:34 day 2 — matches `scripts/cic_ddos2019_syn_windows.json`
exactly) **AND** a per-window SYN-count threshold as a corroborating gate.

The team's explicit concern (their words): they don't want ground truth to
lean on "just counting the TCP [SYN packets] and labeling based on that" —
they want "a scientifically correct way to identify them and cluster them,
then we go to the model training phase which actually does the detection."
In other words: decouple label construction from a single counting
heuristic, using real flow-derived statistical features and unsupervised
validation, so the paper can honestly claim the CNN learns genuine visual
attack structure from the image — not restating the rule it was labeled by.

## Scientific design decision

**Do not let unsupervised clustering blindly override the CIC schedule.**
Because the "normal" region of the training day contains other attack types,
naive k=2 clustering on packet-rate/byte-count-style features could just as
easily separate "SYN vs other-attack" as "SYN vs benign," or produce a
spurious 3rd mode — trusting it blindly would risk a *worse*, less
defensible labeling than today's heuristic.

Adopted design — **cross-validate two independent signals, drop what they
disagree on**:

1. `candidate_label = "ddos" if schedule_overlaps_utc_window(...) else "normal"`
   — the schedule alone, reusing the existing (unchanged) primitive. This is
   the part the team already trusts as real ground truth.
2. Build a genuine multi-feature per-window statistical representation from
   full 5-tuple + flag + timing data (not just SYN count), and run
   unsupervised clustering (KMeans k=2 primary, GMM/DBSCAN as robustness
   cross-checks) **per capture day**, standardized.
3. Cross-tabulate cluster assignment vs. `candidate_label`.
   - **Agree** → keep as `validated_label` (two independent methods concur).
   - **Disagree** → window is ambiguous, **dropped from training** (not
     forced either way).
4. Report `silhouette_score` + agreement-% per day in a markdown report —
   this is the paper's separability evidence.
5. **Hard-coded, code-enforced fallback**: if silhouette < 0.15 for a day,
   auto-switch that day to `resolution_mode="schedule_priority"` (keep 100%
   of schedule labels, drop nothing, clustering reported only as a weak
   validation metric) — so "don't manufacture a result if it's not clean" is
   enforced by the script, not a judgment call made under deadline pressure.
6. Raw `syn_count`/`syn_ratio` becomes one input feature among ~14, not the
   deciding rule — this is what lets the paper say the label and the CNN's
   input were derived independently of a single counting heuristic.

If clustering ends up agreeing with the schedule almost everywhere (possible
outcome), that is *itself* a legitimate, honestly-reportable finding:
"independent unsupervised clustering on flow features corroborates the
official schedule-based ground truth with X% agreement, silhouette Y" — not
a failure of the exercise.
