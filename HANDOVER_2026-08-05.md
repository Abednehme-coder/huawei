## 1. What's done

- All 5 CICDDoS2019 PCAP zips downloaded, verified, converted to both
  byte-dump and flowpic image encodings (96,770 PNGs each). Blocked/
  cross-day split done for flowpic (bytedump split still not run — remains
  deprioritized, not cancelled). See `HANDOVER_2026-08-04.md` §1 for full
  detail, unchanged since then.
- **Supervised flowpic model — final state**: kept the epoch-22 checkpoint
  from the original 40-epoch run (`model/flowpic_0p3_validated_v1/resnext50_32x4d_best.ckpt`,
  val `f1_ddos=0.830`) rather than risk a 5th power-loss restart, **then**
  ran a follow-up fine-tune continuation
  (`scripts/train_resnext_flowpic_v1_continue.sh`, lower LR, fresh 18-epoch
  cosine schedule from those weights) which improved to val `f1_ddos=0.8656`
  (epoch 16, `model/flowpic_0p3_validated_v1_continued/`). Both checkpoints
  exist on disk; the continued one is the better of the two on val.
- **Autoencoder unsupervised baseline — done, weak result, explained**: val
  `roc_auc=0.288` (below random). Root-caused: ddos-labeled flowpic windows
  are ~3.7x *sparser* than normal ones (SYN flood in 0.3s = concentrated
  pattern; normal traffic = busier), so the autoencoder — which converges to
  reconstructing sparse patterns well — scores ddos as more "normal," not
  less. Genuine negative finding for reconstruction-based detection on this
  representation, not a bug. `model/flowpic_autoencoder_v1/eval_report.json`.
- **Deep SVDD unsupervised baseline — done, also weak, but methodology
  fixed along the way**: first real run hit total hypersphere collapse
  (`val roc_auc=0.002`, predicted every image as ddos) — a real bug in the
  early-stopping design (was keyed on the training objective itself, which
  trivially improves *during* collapse). Fixed with a `--min-embed-std`
  floor that hard-stops training the moment representation variance
  collapses. Fixed run: val `roc_auc=0.287` — still weak, plausibly the
  same underlying cause as the autoencoder (SVDD's encoder starts from
  AE-pretrained weights and doesn't get enough pre-collapse epochs to move
  away from that sparsity-correlated representation). Tried 5x higher LR to
  test that theory — made it worse (`roc_auc=0.242`), which itself supports
  the theory (not a step-size problem, a short-window problem). Current
  best at `model/flowpic_deep_svdd_v1/`; failed/inferior attempts preserved
  alongside with descriptive suffixes for the record
  (`_collapsed_2026-08-04`, `_worse_lr5e-4_2026-08-05`).
- **Val→test gap root-caused** (the session's most important finding): of
  the supervised model's 3,024 test false positives, 97% (2,934) sit in
  exactly the two sub-pcap stems (`SAT-01-12-2018_0617`, `_0619`) that
  contain the labeled attack itself — everywhere else in the entire
  held-out day (450 other stems, 5,370 normal windows) the false-positive
  rate is only 1.68%. This lines up with `reports/cluster_validation_2026-08-01.md`:
  `01-12-2018` is the one day that used `schedule_priority_low_syn_purity`
  fallback labels (cluster validation gate failed, GMM ARI negative)
  instead of genuine cluster-validated labels like `03-11-2018` (train/val's
  source). Very likely: the schedule boundary is narrower than the real
  attack traffic, so thousands of genuinely attack-adjacent windows got
  labeled "normal." Boundary-excluded metric: `acc=0.979, f1_ddos=0.932`
  (better than val). **Strong circumstantial evidence, not yet confirmed**
  — see §2.
